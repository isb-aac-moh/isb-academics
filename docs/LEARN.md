# Learn

The study section at `/learn`. It began as a separate app ("mktg-rep", also called the ISB Learning Agent) with its own Supabase project, and was merged into ISB Academics on 2026-08-14. All of its code lives in `src/learn/`. It uses the same login, database and deployment as the rest of the app but has its own look, navigation and admin.

## What students get

Learn looks like a desktop: the ISB campus photo in the background, a column of icons on the left, and every screen opening as a floating window on top. Escape or the X closes a window. On phones, windows fill the screen and a bottom bar (Home, Learn, Practice, You) replaces the app's normal bottom nav. The main sidebar collapses to icons while you're inside Learn.

| Route | Screen | What's on it |
|---|---|---|
| `/learn` | Home guide | Greeting, XP, day streak, "Start smart practice", a short how-it-works, and the student's progress summary. |
| `/learn/subjects` | Course picker | A card per course. Switched-off courses say "coming soon" (admins see "preview" and can open them). Revision guide cards below. |
| `/learn/sessions/:course[/:session[/:topic]]` | Course, session or topic | Left rail of sessions and topics with search and a tick for mastered topics. The course view has announcements, outline and files. A session has its summary, files, slides link, "Practice this session", "Practice your 2 weakest", and every concept note. A topic has the concept note and "Start practicing". Wide screens get a "Jump to" contents list. |
| `/learn/practice` | Smart practice | Course picker if none is chosen. Links can target a topic (`?course=&topic=`), several topics (`&topics=a,b`) or a session (`&session=`). |
| `/learn/revision/:course[/:session]` | Revision guide | Session cards, then the guide in a frame with tabs and an "Open full screen" link. |
| `/learn/profile` | You | Name, email, progress summary, "Reset progress" (clears mastery; XP and streak stay). |
| `/learn/admin` | Learn admin | Admins only. See below. |

A typical path: Home, pick a course, open a session, read a concept, practise it, see the round summary, go back.

## How practice works

### Mastery

Each student has a level per topic (`src/learn/lib/mastery.ts`):

| Level | Reached when |
|---|---|
| 0 Not started | No attempts |
| 1 Attempted | Any attempt |
| 2 Familiar | 2 correct in a row |
| 3 Proficient | 4 correct in a row |
| 4 Mastered | 6 correct in a row and at least 6 attempts |

A correct answer never lowers the level. A wrong answer drops one level (never below Attempted) and resets the run.

### Picking the next question

`pickNext` in `src/learn/lib/adaptive.ts`:

- A topic answered wrongly goes into a retry queue and comes back after 2 more questions.
- Otherwise the next topic is a weighted random pick. Weights by level are 5, 4, 3, 2, 1, so weak topics come up most but mastered ones still reappear.
- A case scenario (several linked questions sharing one setup) counts as one pick and is always served in order and in full. If it won't fit in what's left of the round, it isn't started.
- A round is 8 questions and can run up to 4 over to finish a retry or scenario. No question repeats within a round. This is why every content generator aims for 8 questions per topic.

### A round, step by step

1. The first time a student meets a topic, a concept card appears before the question.
2. The student picks an answer and presses Submit. A hint is available. A timer turns red after 90 seconds.
3. **Correct:** explanation, +10 XP, streak count. Confetti at 3, 5 and 8 in a row.
4. **Wrong:** a remediation card with what they picked, the concept refresher, the level change, and "You'll see another question on this shortly" when a retry is queued.
5. Skip records nothing. "Review previous" shows earlier questions read-only.
6. **Summary:** score, best streak, overall progress, and a "What moved" list of level changes.

The day streak goes up by one if the student was active yesterday and resets to 1 after a longer gap.

### Question types

| Type | Label | How it's used |
|---|---|---|
| `formula` | Compute it | Multiple choice, played in practice |
| `case_fact` | Case recall | Multiple choice, played in practice |
| `short_answer` | Write it | No choices, stores a model answer. Only shown in the read-only question bank, never played. A course with only these (BANM2) isn't offered in Smart practice. |

Each question also records `difficulty` (1 to 3) and `provenance`: `prof_verbatim` (straight from the professor's material), `prof_adapted`, or `authored`.

### Formula sheet

During practice a "∑ Formula sheet" drawer shows the session's formulas. It is always available because the exams are open-notes.

## Rendering: markdown, maths and widgets

Content is stored as text in a small markdown dialect parsed by `src/learn/components/Markdown.tsx`:

- `##` and `###` headings, `-` and `1.` lists (one level of nesting), bold and italic, pipe tables.
- Callouts with `>` and a prefix: `Trap:`, `Worked example:`, `Prof:`.
- Maths as `$inline$` and `$$display$$`, rendered with KaTeX. KaTeX is its own download, started as soon as Learn loads, with raw TeX shown if it fails.
- Interactive widgets with `:::viz name key=value`.
- No links and no code blocks.

## Data

Learn uses the same Supabase client as the rest of the app (`src/learn/lib/supabase.ts` re-exports `src/lib/supabase.ts`). `src/learn/lib/db.ts` is the only file in Learn that talks to the database. It renames a few columns on the way in (for example `course_code` becomes `course_id`) so the component code from the original app didn't need rewriting.

Tables, all created in `20260813201640_learning_agent_schema.sql` (column detail in [DATA_MODEL.md](DATA_MODEL.md#learn-tables)):

- **Content** (readable by everyone, only admins write): `learn_courses`, `learn_session_content`, `learn_course_content`, `learn_concepts`, `learn_questions`, `learn_scenarios`, `learn_materials`.
- **Per student** (each student reads and writes only their own rows): `learn_profiles` (XP, streak), `learn_attempts` (every answer), `learn_topic_mastery` (level per topic).
- **Storage bucket** `course-materials`: private, 50 MB limit, PDF and Office files. Signed-in users get 1-hour links; admins upload.
- **Admin statistics functions:** `learn_admin_cohort_stats`, `learn_admin_topic_stats`, `learn_admin_flagged_questions`. Each checks the caller is an admin.

`learn_courses.course_code` references `courses.code`, so a Learn course must already exist in the main course catalogue.

## Learn admin (`/learn/admin`)

Separate from the main admin panel. Every tab except Monitoring has a course selector.

| Tab | What an admin can do |
|---|---|
| Monitoring | Students, active today, active this week, questions answered, accuracy. Accuracy per topic. Flagged questions (3+ attempts with accuracy under 40% or over 95%, which usually means a wrong answer key or a giveaway). |
| Questions | Add a compute or case-recall question with 2 to 4 choices, source, scenario, difficulty and provenance. List and delete. |
| Scenarios | Create, edit and delete case setups. |
| Concepts | Add or edit concept notes; delete. |
| Sessions | Set the number of sessions; edit each session's title, summary, formula sheet and slides link. |
| Materials | Upload files to a session; open and delete. |
| Course | Switch a course on or off; edit announcements, outline and links (cheatsheet, sample exams, feedback). |

The admin forms are fine for small fixes. Bulk content goes through the generator pipeline below. See [ROADMAP.md](ROADMAP.md#known-bugs-and-rough-edges) for what the admin forms can't do yet.

## Adding content: the generator pipeline

Bulk content is written as Python, turned into SQL, and applied as a database migration.

1. Write or extend a generator in `supabase/` (for example `supabase/madm-practice-bank.py`). Content is defined as Python data: sessions, concepts, questions, scenarios.
2. Use the checks in `supabase/practice_lib.py`:
   - `check_question`: the correct answer must be one of the choices; written-answer questions must have no choices; difficulty and provenance must be valid.
   - `check_markdown`: only the supported markdown subset.
   - `check_inline_math`: catches a `$` price being read as maths.
   - `shuffle_choices`: shuffles choices with a seed based on the question id, so reruns give the same order.
   - `sql` and `json_array`: safe quoting.
3. Run it into a new migration: `python3 supabase/<generator>.py > supabase/migrations/<timestamp>_<name>.sql`.
4. Apply with the Supabase CLI (`supabase db push`). Never paste into the dashboard's SQL editor; see [ARCHITECTURE.md](ARCHITECTURE.md#database-changes).

Rules learned the hard way:

- **Never hand-edit generated SQL.** Change the generator and regenerate.
- **Changing content needs a new migration file.** Applied migrations don't run again.
- **When re-emitting a course, strip the `learn_courses` insert**, or it will reset the course's on/off switch.
- Generated statements upsert or skip on conflict, so a rerun is safe.
- To hold back a course until its code ships, insert it switched off and switch it on in a later migration, as `20260814150100_banm2_hold_until_deploy.sql` and `20260814160000_banm2_enable.sql` did.

Existing generators: `banm2-content.py` (predates `practice_lib`), `banm2-expansion.py`, `madm-content.py`, `madm-practice-bank.py` (refuses to run if expected counts drift), `mktg-expansion.py`, `opmg-additional-set.py`, `opmg-expansion.py`. Some early OPMG and MKTG migrations were generated by scripts that were never committed, so for those the migration SQL is the only source.

## Design
